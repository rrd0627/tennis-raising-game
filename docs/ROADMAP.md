## 플레이 시간 예산

**1주 1행동과 하이라이트 기본으로 약 8시간까지 줄였다.** 예전 구조는 21~25시간이었다. 아래는 추정치이고, 1단계에서 실측해 고친다.

| 항목 | 계산 | 시간 |
| --- | --- | --- |
| 1회차 상한 | 기획 문서 목표 8시간 | 480분 |
| 턴 진행 | 156턴 × 30초 (가정) | 78분 |
| 이벤트·메뉴 | 가정 | 60분 |
| 경기에 쓸 수 있는 시간 | 480 − 78 − 60 | 342분 |

- 하이라이트를 경기당 약 3분으로 잡으면 114경기까지 들어간다. 전체 1×는 경기당 약 6분(약 355샷 × 1초)이라 57경기다.
- 지금 자동 플레이는 3년에 대회 29~40회, 경기 81~135회(중앙값 114회)다. 대회 1회는 약 3경기다.
- 플레이어가 월 2회 이상 나가거나 1×로 보면 8시간을 넘는다.

## 아트 계획 (AI)

**가장 큰 위험은 같은 캐릭터가 포즈와 표정마다 같은 사람으로 보이는 일관성이다.** 아트 명세서는 사람이 그리는 전제라 출시 범위를 줄인다.

| 종류 | 명세서 전체 | 출시 제안 | 이유 |
| --- | --- | --- | --- |
| 경기 스프라이트 | 14세트 × 170프레임 = 2,380장 | 8세트 × 16장 = 128장 | 지금 엔진은 포즈 8개 × 앞뒤만 쓴다. 움직임은 코드로 처리 |
| 세트 구성 | 주인공, 파트너 8, 일반 상대 2, 라이벌 3 | 주인공, 파트너 4, 일반 상대 2(색 변형), 라이벌 1 | 일반 상대 색 변형은 명세서 방식 유지 |
| 스탠딩 | 17명, 얼굴 파츠 조합 | 10명 × 표정 5종 = 50장 | 파츠 레이어는 AI 그림과 맞지 않아 표정별 통그림으로 |
| 컷인 | 22장 | 6장 | 주인공 중심 |
| 배경 | 13장 | 8장 | 활동 8종 안팎에 맞춤 |
| 이벤트 CG | 12장 | 6장 | 잘라도 게임이 돌아감 |
| 엔딩 | 12장 | 12장 | 다회차 동기라 유지, 기존 그림 재활용 허용 |
| 인트로 | 없음 | 정지 컷 6장 + 자막·효과음 | 기획 문서 12장의 컷 흐름. 영상 대신 넘기는 컷으로 |

작업 순서는 다음과 같다.

1. 기존 컨셉 그림에서 기준 그림을 골라 주인공 스탠딩 1장과 경기 포즈 16장을 만든다.
2. 파트너 1명을 같은 방법으로 만들어 나란히 비교한다. 3명에게 같은 게임으로 보이는지 묻고, 아니면 스타일을 더 단순하게 바꾼다.
3. 배경 제거, 384×384 크기와 발 기준점 통일, 시트 묶기, `art/manifest.json` 등록을 `tools/` 스크립트로 자동화한다.
4. 슬라이스에 필요한 그림부터 넣고, 장당 제작 시간을 재서 전체 일정을 다시 계산한다.
5. 그림마다 도구, 날짜, 프롬프트를 `art/SOURCES.md`에 남긴다.

## 일하는 방식

- 한 주에 목표는 하나만 두고, 금요일마다 플레이 가능한 빌드와 한 줄 기록을 남긴다.
- 새 아이디어는 필러와 현재 단계의 통과 기준에 필요할 때만 넣고, 아니면 "나중에"로 보낸다.
- 할 일은 GitHub Issues에 단계별 Milestone으로 정리한다. 저장소가 공개인 동안에는 Issues도 공개된다.
- 플레이테스트는 도와주지 않고 지켜본다. 어디서 멈추는지 기록하고 구글 폼으로 후기를 받는다. 이 기록은 프로덕션 신청 설문에도 쓴다.
- 엔진을 고치면 `npm run balance`, 턴·성장을 고치면 `node tools/season.js`를 돌린다. 2단계에서 GitHub Actions로 자동화한다.
- 결정이 나면 이 문서, `CLAUDE.md`, 기획 문서 순서로 고친다.
