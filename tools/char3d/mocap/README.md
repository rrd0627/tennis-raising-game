# 모션캡처 → 3D 스윙 키

공개 모션캡처 자료를 이 게임의 스윙 키(`js/swings_mocap.js`)로 바꾸는 도구다. 사용자 요청(2026-11-11: 영상·공개 자료를 토대로 동작을 고치자)으로 만들었다.

## 자료

- Tennis-MoCap: https://github.com/jdpulgarin/Tennis-MoCap
- 콜롬비아 칼다스 지역 테니스 리그 선수 17명을 광학 모션캡처(초당 100프레임, BVH)로 찍었다. 서브, 스매시, 포핸드, 포핸드 발리, 백핸드, 백핸드 발리를 30초씩 여러 번 친다.
- 라이선스: CC BY-SA 3.0(크리에이티브 커먼즈 저작자표시-동일조건변경허락). 바꾼 키(`js/swings_mocap.js`)도 같은 라이선스로 공개하고, 게임의 ⚙️ 설정에 출처를 적는다.
- 쓰는 것: 일반 수준(RP) 여자 선수 세 명(자료의 labels.csv에 여자 일반 수준은 이 셋뿐). C는 포핸드·양손 백핸드·포핸드 발리·서브·스매시, A는 한 손 백핸드 발리. 원본 파일 이름에 선수 이름이 있어 저장소에는 A·B·C로만 적는다.
- 사람마다 다른 폼(2026-11-20): `convert.py`의 `VARIANTS`가 A·B의 샷을 `fh@A` 같은 이름으로 뽑고, `run.mjs --only=fh@A,...`로 키와 고침을 굽는다. 게임은 `js/swings.js`의 `FORMS`로 선수마다 한 사람의 폼을 쓴다. 관절 검사(`node tools/char3d/jointcheck.mjs fh@A ...`)에서 라켓이 공에 못 미치거나 관절이 튄 것은 `js/swings_mocap.js`에서 뺐다(A의 fv·fs·sv, B의 fh·sv).

## 하는 일

1. `convert.py`: BVH를 읽어 관절 자리와 회전을 구한다(`bvh.py`). 샷마다 여러 번 친 것 중 가장 흔한 한 번을 고른다.
   - 임팩트를 0초로 맞춘다. 땅볼은 손목이 가장 빠른 때 라켓 머리가 아직 뒤에 처져 있어서, 라켓이 네트와 나란해지는 때로 잡는다. 서브·스매시는 라켓이 가장 곧게 선 때로 잡는다.
   - 0.05초 간격으로 골반 자리와 돌기, 가슴 회전, 발(앞꿈치 자리, 발끝 방향, 뒤꿈치 각), 손목 자리와 팔꿈치 방향(가슴 기준)을 뽑는다. 라켓 방향은 손목 회전에서 얻는다.
   - 손잡이 축은 양손 백핸드에서 오른손목 → 왼손목 방향이 손목에 대해 거의 일정한 것(가운데 7~11도)으로 맞춘다. 줄 면은 임팩트 때 네트 쪽을 본다고 보고 샷마다 맞춘다. 쥐는 법은 포핸드를 세미웨스턴(-40도)으로 두고 샷마다 정한다. 그러면 서브가 컨티넨탈(+45도)에 온다.
   - 발끝 방향은 발목 회전의 옆 축으로 구하고 이어지게 편다. 팔이 거의 펴져 팔꿈치 방향을 읽을 수 없으면 이웃 값으로 메운다.
2. `run.mjs`: 스윙 화면을 화면 없이 열어 `build_keys.js`를 돌린다.
   - 골반·가슴·발은 리그 몸 크기(골반 높이 비)에 맞추고, 가슴은 실제 가슴 방향과 맞을 때까지 고친다.
   - 손목은 리그 어깨 + 가슴 방향 × (모션캡처 손목 - 어깨) × 팔 길이 비로 둔다.
   - 왼손이 라켓을 잡고 놓는 것은 0.25초쯤에 걸쳐 바뀌게 한다. 양손 백핸드 왼손을 돌려 쥐는 각(`lroll`)은 왼손목이 가장 편한 쪽으로 고른다.
   - 임팩트를 몸 앞으로 옮긴다: 라켓 가운데가 골반 앞 42~45cm(`AHEAD`)에 처음 오는 때를 0초로(사용자 2026-11-11: 공이 임팩트 지점을 지나쳤다가 돌아가는 느낌).
   - 발리는 짧고 빠르게: 임팩트 앞 시간 1/1.7, 뒤 1/1.5, 손 자리·라켓 방향·몸 돌기 폭을 줄인다(`tk`, 디딜 때도 같이 줄인다).
   - 다 되면 `js/swings_mocap.js`를 쓰고, 라켓이 몸을 뚫지 않게 하는 고침(`cor`)을 구해 같이 굽는다. 고침만 다시 구우려면 `node tools/char3d/mocap/run.mjs --bake`.

## 다시 만들기

```
# 1) BVH 18개를 tools/char3d/mocap/raw/에 받는다(커밋하지 않음): A·B·C의 Derecha, Reves, VDerecha, VReves, Servicio, Remate
python -I tools/char3d/mocap/convert.py      # clips.json
npm run serve                                 # 다른 창에서
node tools/char3d/mocap/run.mjs               # js/swings_mocap.js
node tools/char3d/mocap/run.mjs --only=fs,bs  # 그 샷만 새로 만들어 넣는다(다른 샷의 키·고침은 그대로). 슬라이스(fs, bs)는 발리 자료를 줄이지 않고 허리 높이로 맞춘 것
node tools/char3d/jointcheck.mjs              # 관절 검사
```

시험 화면 '동작' 버튼으로 손으로 짠 동작과 견줘 볼 수 있다(`?src=hand`). 손으로 짠 키는 `js/swings.js`에 그대로 있고, 경기에서 기다리는 자세(준비 자세)로 쓴다.

## 이동 동작(걷기·달리기, 2026-11-16)

경기의 3D 선수가 기다리고 움직이는 동작(이동 엔진 `js/loco3d.js`)의 재료다.

- 자료: The 100STYLE Dataset, Neutral 스타일 8개(FW 앞으로 걷기, FR 앞으로 달리기, BW·BR 뒤로, SW·SR 옆걸음, ID 서 있기, TR1 바뀌기). https://www.ianxmason.com/100style
- 라이선스: CC BY 4.0. 바꾼 자료(`art/char3d/loco.bin`)도 출처를 적어 쓴다(게임 ⚙️ 설정).
- XSens 60fps, 한 사람. 좁은 곳에서 찍어 달리기가 초속 2.2m까지라 게임이 빨리 틀고 보폭을 늘린다.

```
# 1) BVH 8개를 tools/char3d/mocap/raw/100style/에 받는다(Neutral_FW.bvh … Neutral_TR1.bvh, 커밋하지 않음)
python -I tools/char3d/mocap/loco.py        # art/char3d/loco.bin
```

**CMU 달리기 동작(2026-11-24, 사용자: 뛰는 것을 다양한 애니메이션으로).** 100STYLE은 달리기가 초속 2.2m까지라 실제 빠르기의 동작을 더한다.

- 자료: CMU Graphics Lab Motion Capture Database(http://mocap.cs.cmu.edu), 모든 쓰임에 자유(원본을 그대로 팔지만 않으면). 인용: "The data used in this project was obtained from mocap.cs.cmu.edu. The database was created with funding from NSF EIA-0196217."
- 동작 52개(`loco.py`의 `CMU_CLIPS`): 농구 78번(곧게·크게·좁게 도는 달리기, 수비 옆걸음 좌우·지그재그, 멈췄다 출발, 피벗, 페인트, 드라이브), 104번(달리기·조깅 출발·멈춤·지나가기), 141·143번(달리기, 달리다 멈추기, 서서 출발), 141번(옆으로 크로스·발 붙이며 옆걸음), 16번(급정지, 90도 꺾기). 104_01은 뿌리가 한 프레임에 튀어, 104_55는 2.6초부터 끝까지 오른발 자료가 90도 넘게 돌아 있어 뺐다.
- ASF·AMC를 `raw/cmu/`에 받는다(커밋하지 않음): `http://mocap.cs.cmu.edu/subjects/<사람>/<사람>.asf`, `.../<사람>_<번호>.amc`. `asfamc.py`가 읽어 100STYLE 관절 이름으로 바꾸고(골반·가슴 회전은 자리로 만든 틀, 발목은 발 뼈 회전의 가로축으로. 발끝 자리로 내면 달리며 뒤로 차 올린 발에서 앞뒤가 뒤집혀 게임에서 무릎이 뒤로 꺾였다), 다리 길이(뼈 길이 합)를 100STYLE에 맞춰 키운다(사람마다 키가 다르다). 120fps를 30fps로 줄이고, 0.8초보다 긴 구간만 쓴다.
- 잰 값(확인 링크 60초): 초속 2.5m 넘게 움직일 때 CMU 동작을 쓴 몫 68%, 그때 빨리 틀기 가운데값 1.62 → 1.37배, 보폭 늘리기 1.36 → 1.12배.

`loco.py`는 T자세 앞뒤 1초를 빼고 30fps로 줄인 뒤, 프레임마다 뿌리(골반을 바닥에 내려 편 자리와 골반·어깨 앞쪽을 편 방향), 뿌리 기준 골반·가슴·발(앞꿈치 자리, 발끝 방향, 들림, 뒤꿈치 각), 발 닿음(앞꿈치 높이 4.5cm 아래, 빠르기 초속 0.4m 아래)을 남긴다.
